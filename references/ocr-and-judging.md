# OCR 与作答判定

本文件是把扫描件变成可信内容的方法。核心是**三重交叉验证**，以及**判不出来就标注**。

## 1 版面定位

先看清一页上有哪些块，再决定裁哪一块去 OCR。

- `pixel_map.py`：把区域打成 ASCII 密度图。`#` 深色、`+`/`.` 由深到浅、`R` 红笔、空格是空白。用它找题干边界、选项行、答题卡格子。
- 密度阈值参考：`gray = 0.3R + 0.59G + 0.11B`；`dark = gray < 145~150`；`red = (R > 90) & (R - G > 25~35) & (R - B > 25~35)`。
- 扫描件方向不正：先 `rotate_image.py` 摆正，再 OCR；倾斜会显著降低识别率。
- 整页 OCR 效果差时，切成「题干块 / 选项块 / 答题格」分别识别，再拼接。

## 2 OCR 题卷

- `ocr_region.py <img> x1 y1 x2 y2 [scale]`：裁剪 + 放大（默认 3×）后识别。小字、印刷体放大后准确率高很多。
- 目标是拿到**完整原文**：题干、全部选项、材料/图表说明。缺一个选项就可能误判干扰项。
- 数学、物理、化学的公式与符号 OCR 常出错，必须人工核对；把公式写成 `@@…@@` 放进正文。

## 3 判定答卷

### 3.1 客观题涂卡（像素灰度）

涂黑的选项格子平均灰度明显低于空白格子。

- `option_scan.py <img> x1 y1 x2 y2 [n]`：把一行等分成 n 格，输出每格的深色像素占比，最深的一格通常就是所选。
- 选项间距不均匀时用 `pixel_map.py` 先量出每个选项的中心 x，再逐格采样。
- `solid_blobs.py`：连通域找实心块，用来确认「涂黑」而不是「印刷的字母」——涂黑块 fill（面积/外接框）高、接近方形。
- **交叉核对**：老师红笔打勾 / 打叉的位置应与涂卡一致；不一致时以红笔 + 灰度为线索再确认。

### 3.2 主观题手写

- `ocr_handwriting.py <img> x1 y1 x2 y2 [scale]`：先滤掉红笔（只留黑色笔迹）再识别，避免老师红字干扰学生字迹。
- 逐格辨认，一格一格来；手写潦草时结合上下文猜，但**只写能确认的字**。
- 老师红笔的改错（✗、红字改正、扣分）是重要线索：它能直接告诉你「这题错了、错在哪」。

### 3.3 题卷原文

从题卷 OCR 出的题干与选项，独立推出正确答案，作为第三路验证。

### 3.4 结论

- 三路一致 → 写「确认」。
- 只有两路、或某一路读不清 → 写「待确认」，并在交付说明里列出题号，请用户核对。
- **绝不把「看起来像」当成结论。**

## 4 诚实性规则

1. 学生作答一律以答卷为准；题卷上的答案只作对照。
2. 无法确证的一律标注「待确认」，不编造学生的答案。
3. 用户要求忽略的部分（如英语听力）不收录，并在输出里写明。
4. 交付时说明：本次归集了多少题、哪些题待确认、哪些题因图片质量未收录。

## 5 Windows / 中文环境注意

- 中文路径用 `-LiteralPath`、单引号，或先切到工作目录；不要用 `ls -la` / `head`，用 `Get-ChildItem` / `Select-String`。
- Python 读写文本显式指定 `encoding="utf-8"`；控制台是 GBK 时，子进程输出加 `errors="replace"`。
- 不要把长段 Python 源码塞进命令行字符串，写成 `.py` 文件再跑；跑前 `python -m py_compile` 过一遍。
